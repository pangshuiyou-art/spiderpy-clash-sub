# README.md — 记忆协议（模板）

所有在本项目协作的 AI Agent（Claude / Trae / WorkBuddy / Cursor / Cline / Gemini / GPT / 未来的任何 agent）**必须**遵循本协议。

## 一、读写总则

- **会话开始第一步**：读 `.memory/MEMORY.md`（索引总览），再按需进入对应主题条目。
- **任务认领 / 状态**：走协作看板（如 `docs/任务看板.md`），**不**写进 `.memory/`。
- **长期记忆唯一事实源**为 `.memory/`；**禁止**把长期项目记忆写入各软件私有目录当作长期记忆（如 `~/.trae-cn/`、`~/.claude/`、`~/.workbuddy/` 等），这些仅作运行态中间层。

## 二、目录职责

| 目录 | 写什么 |
|------|--------|
| `user/` | 用户偏好、工作方式（每文件一条） |
| `project/` | 项目长期约束、架构决策——**不可从代码推导**的部分 |
| `learnings/` | 踩坑、经验、bug 调查结论 |
| `archive/` | 会话/过程流水，按 `YYYY-MM/` 归档；原文保留在各工具私有记忆 |

## 三、条目格式

- **命名**：`YYYYMMDD-slug.md`（日期前缀 + 主题），shell 排序即时间序、grep 可见、避免并发撞名。
- **frontmatter**（文件顶部）：

```markdown
---
name: <条目名>
description: <一句话说明>
type: user | project | learning
created: 2026-08-24
updated: 2026-08-24
---
```

- 正文：一条记忆一个文件，**聚焦单一主题**。

### 条目写法建议（实战积累）

- **project/ 硬约束条目**：只记"不可从代码推导"的内容——架构红线、常量位置、数据一致性约定、已知坑。每条给结论 + 位置，别写成代码能看出来的东西。
- **learnings/ 踩坑条目**：遵循「背景 → 根因 → 修复 → 自愈机制」四段式，重点写**根因**；结论要能让下次直接避开同类坑。
- 正文用中文，代码标识符、路径、API 名可保留原文。
- 一条文件写不下连贯主题时，宁可拆两条也别糅合。

## 四、写入与提交纪律

1. 有可沉淀记忆时，新建条目文件到对应目录。
2. 更新 `MEMORY.md` 的"最近条目"与"分类索引"两处——**只允许追加自己条目对应的行，禁止改动他人行**。
3. `git add <条目文件和 MEMORY.md>` + `git commit -m "docs(memory): <one-line>"`。
4. commit 前先 `git pull --rebase`，防多 agent 冲突；若索引提交冲突，rebase 后重试追加。
5. `MEMORY.md` 索引采用"**各自追加、互不改动他人行**"规则；条目重排、清理、去重由**单一维护者**定期执行，其余 agent 不得代做。

## 五、保密红线

- **禁止**写入 token / 密码 / 密钥 / 未脱敏凭证。
- 禁止写入项目禁止提交的敏感文件内容（如 `.env`、`settings.json` 等，按各项目红线）。

## 六、诚实边界

没有任何机制能真正"强制"一个 agent 读本协议；最接近强制的是：本协议写入 `AGENTS.md` / `CLAUDE.md` **顶部** + `MEMORY.md` 作为不可绕过的启动点 + git 使违反可观测。请各 agent 自觉遵守。
