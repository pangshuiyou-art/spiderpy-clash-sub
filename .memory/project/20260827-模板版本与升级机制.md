## 机制约定（v1.2 引入）

- **版本唯一事实源**：`00_模板使用说明.md` 头部的"模板版本历史"表（版本 | 日期 | 变更摘要 | 是否破坏性）。该文件复制到项目后**必须保留**（v1.2 起启用清单第 10 步已改），它是目标项目的版本锚点。
- **主副本路径**：`00_模板使用说明.md` 头部"模板主副本路径"占位在启用时填入（本仓库即 `E:\PJdemo`），目标项目靠它找到最新版模板。
- **采用记录**：每个项目启用模板时必须在 `.memory/project/` 写 `YYYYMMDD-采用模板vX.Y.md`（版本号 + 主目录路径 + 本地偏差初盘）。它是升级流程的事实起点——没有采用记录，agent 无法判断项目当前处于哪个版本。
- **升级闭环**：目标项目 agent 收到"检查模板更新"指令时，按 `docs/启用与升级提示词.md` 场景四执行：查采用记录 → 对比主目录版本历史表 → `git -C 主目录 diff tpl-vX..tpl-vY` → 盘点本地偏差（保护对象）→ 增量分三类（直接合入/就地更新/用户裁决）→ 更新采用记录并单独提交。
- **发布新版本四步**（模板维护者）：递增版本号 → 版本历史表追加行（破坏性变更必须附迁移说明）→ 主目录 git 打标签 `tpl-vX.Y` → 同步修订提示词文档中受影响的提示词文本。

## 为什么这样设计（不可从文件推导的部分）

- 各项目启用后都会填占位符、删示例骨架，**项目内文件 ≠ 模板原文**，所以升级必须"先盘本地偏差再合增量"，绝不能整目录覆盖——这是场景四第 2 步存在的根本原因。
- git 标签（`tpl-v1.0`/`tpl-v1.1`/`tpl-v1.2`...）让任意两版本间可精确 diff，是升级时"精确差异"步骤的数据基础；发版必须打标签，否则升级流程退化为主观比对。
