- 计划文档：`docs/方案_聚合订阅节点保留机制_20261011.md`；实现：`scripts/sub_aggregator/node_ledger.py` + `pipeline.py` 接入 + `output_builder.py` 保留组 + `aggregate-sub.yml` 提交台账。
- 质量标准零改动：主组只放当轮 mihomo 连续 N 轮通过节点；保留组（`住宅-保留`/`日常-保留` select 组）只装「历史通过≥3 轮、连败 1~2、7 天内验证过」的观察节点。
- 既有订阅链接零改动（约束达成）；tests/docs 不上远端的纪律保持。

## 关键参数（改动前先读）

- 回测预算：住宅 300 / 日常 800 / socks4 300（TCP 预筛前置后进 mihomo，CNB 增量 <1 分钟，crontab 未动）
- 淘汰线：连败 ≥3 或 7 天无验证成功；台账上限 5000 条按末次验证裁剪
- 稳定命名：键=(protocol,server,port)，名字终身跟随；分类变化导致 [R]/[D] tag 变化时重新分配；序号只增不复用
- 台账只记 `record_kind='proxypool'`（含 socks4）；链接型节点（vmess 等）不入台账（避免仓库存凭据 + 订阅源重列稳定）
- 台账路径=产物目录下 `known_nodes.jsonl`（CNB 因 `--out-dir data/cnb_shadow/free_proxy` 自动落影子目录，`.cnb.yml` 无需改动）
