# 启用与升级提示词速查（AGENT 自助文档）

> **本文件是给 AI AGENT 看的操作手册**：当用户要求"用那套项目模板 / 启用规则文件 / 检查模板更新"时，agent 按第一节判定当前场景，然后原样使用对应章节的提示词（或直接按提示词执行），不必等待用户补充细节。
> 模板主目录默认为 `{{模板主目录路径}}`（如 `E:\PJdemo`）；升级机制与版本历史见 [00_模板使用说明.md](../00_模板使用说明.md)。

---

## 一、状态判定决策树（先执行这一步）

进入目标项目目录后，按顺序检查，命中即停：

```
1. 目录里有 .memory/ 且其中存在"采用记录"条目
   （.memory/project/*-采用模板vX.Y.md）
   → 【已启用】走 场景四：模板升级流程

2. 有 CLAUDE.md 或 AGENTS.md（或其他既有规则文件），但没有 .memory/
   → 【有规则未启用】走 场景三：合并增量（⚠️ 严禁覆盖现有规则）

3. 目录有代码/文档但没有 CLAUDE.md / AGENTS.md，也没有 .memory/
   → 【无规则未启用】走 场景二：启用 + 回填

4. 基本是空目录
   → 【新项目】走 场景一：整套启用
```

**通用安全红线（所有场景生效）**：禁止 `git stash` / `reset --hard` / `clean -fd`；禁止覆盖、批量改动用户的已有文件；冲突和不明白的地方停下来问用户。

## 二、场景一：新项目 / 空目录（整套启用）

```text
本目录是一个全新的空项目。请把 {{模板主目录路径}} 这套 AI Agent 协作模板启用到本项目，按其 00_模板使用说明.md 第二节执行：

1. 先读 {{模板主目录路径}}\00_模板使用说明.md 和 docs/template_enhancement_inventory.md，理解每个文件的用途；
2. 若本目录还不是 git 仓库，先 git init；
3. 把模板全部文件复制到本目录（含 .memory/、.editorconfig、.gitattributes；.claude/ 与 docs/ 附录按需保留）；
4. 访谈我确认：项目名、一句话简介、技术栈及锁定原因、目录分层、是否有重构复刻来源，然后替换所有双花括号占位符（形如「项目名」等，以脚本扫描结果为准）；
5. 兜底检查 python scripts/verify/verify_placeholders.py（或 grep -rn '{{' AGENTS.md CLAUDE.md），确认无遗漏占位符；
6. 按我的回答补写「常见陷阱」节的初稿占位提示；
7. 必做：新建一条真实 project/ 记忆条目记录本次启用决策与技术栈约束，并另写一条"采用记录"（YYYYMMDD-采用模板vX.Y.md：采用的模板版本号 + 模板主目录路径 + 本地偏差初盘），更新 MEMORY.md 索引（只追加自己的行），单独 commit；
8. pyproject.toml.sample 改名为 pyproject.toml 并填 [project] 元信息；requirements.txt.sample 改名为 requirements.txt 并按项目填写版本号（严格 包名==版本号）；gitignore.example 审查后改名为 .gitignore；
9. 最后删除 docs/template_enhancement_inventory.md 和 AGENTS.md/CLAUDE.md 中的"示例骨架"注释块（保留 00_模板使用说明.md 作为版本锚点），提交规范为 <type>(<scope>): <subject> 中文提交。
每一步做完向我汇报再继续。
```

## 三、场景二：旧项目、没有任何规则文件（启用 + 回填）

```text
本项目已存在代码但没有 AI 协作规则。请把 {{模板主目录路径}} 的模板启用进来，注意不要臆测项目情况：

1. 先扫描本项目结构（目录树、入口文件、依赖清单、git log 近期提交风格），摸清现状后再动文件；
2. 按 {{模板主目录路径}}\00_模板使用说明.md 第二节复制模板与工具配置（.editorconfig / .gitattributes 若与现有约定冲突，停下来问我）；
3. 根据扫描结果填写 AGENTS.md / CLAUDE.md 的占位符：项目身份、技术栈锁定表（必须逐项写出"为什么锁"，从我现有的 requirements.txt / package.json 等取真实版本）、目录分层、常用模块速查、快速上手命令；
4. 「常见陷阱」节暂留通用示例即可，标注"待积累"；
5. 必做：写入采用记录 .memory/project/YYYYMMDD-采用模板vX.Y.md（采用版本号 + 模板主目录路径 + 本次梳理出的架构决策即本地偏差初盘）；
6. 若 git 仓库不存在则初始化；首次提交前问我要不要把现有工作区状态列出来给你看（禁止自动 stash / reset）;
7. 写一条 project/ 记忆条目固化本次梳理出的架构决策，更新索引后单独提交；
8. 启用完运行一次 python scripts/verify/verify_placeholders.py 兜底检查，汇报启用前后差异清单。
```

## 四、场景三：旧项目、已有规则文件（合并增量，禁止覆盖）⚠️ 最需小心

```text
本项目已有 CLAUDE.md / AGENTS.md（或类似规则文件）。目标是吸收 {{模板主目录路径}} 模板的增量约束，严禁覆盖已有内容：

1. 只读阶段：完整阅读我现有的 CLAUDE.md / AGENTS.md 及模板的同名文件，输出一份对照表：现有文件已有哪些条目、模板多出哪些增量（记忆协议 .memory/、Git 操作纪律、修改前自检、测试纪律、每 5 轮自查、文件存放规定、工具配置资产）、两边有冲突的地方；
2. 冲突裁决：把冲突项逐条列给我，等我裁定以哪边为准（例如换行符、行长、格式化工具不同时，以项目现状优先，除非我要求统一到模板）；
3. 合并阶段：经我确认后，只把「现有文件缺失的增量章节」合并进现有文件对应位置，保持原有章节和措辞不动，合并处标一行来源注释；
4. 追加进来的「★ 回复语言/回复结构」等硬性节放在文件顶部，并注明"权威源：AGENTS.md，双份同步维护"；
5. .memory/ 目录整体新增到本项目根目录（若已有类似记忆机制，先把旧记忆迁移成模板 frontmatter 格式再并入，原文件不删）；
6. 工具配置（pyproject.toml / .editorconfig / .gitattributes 等）只有在本项目没有同类配置时才落地，有则以现有为准并把差异告诉我；
7. 写入采用记录 .memory/project/YYYYMMDD-采用模板vX.Y.md（版本号 + 主目录路径 + 合并报告要点）；
8. 全程允许 git add 指定文件，禁止 stash / reset --hard / checkout -- .；
9. 合并完成后给我一份"合并报告"：新增了什么、哪里冲突怎么裁的、哪些模板内容判定不适用于本项目而未引入。
```

## 五、场景四：模板升级流程（已启用的项目追上新版本）

> 触发方式：对项目里的 agent 说一句 **"检查模板更新，如有新版本按升级流程执行"** 即可；升级前必读 [00_模板使用说明.md](../00_模板使用说明.md) 的"模板版本历史"，了解两版之间改了什么、是否有破坏性变更。

```text
本项目此前基于模板 vX 复制（见 .memory/project/ 采用记录）。请把项目升级到 {{模板主目录路径}} 的最新版本：

1. 版本对比：读本项目的采用记录确认当前版本 X 与主副本路径；读 {{模板主目录路径}}\00_模板使用说明.md 头部的最新版本号 Y 与"模板版本历史"表，明确 X→Y 的变更摘要和是否破坏性变更；必要时用 git -C {{模板主目录路径}} log/diff tpl-vX..tpl-vY 查看精确差异；
2. 本地偏差盘点：逐个比对本项目的 AGENTS.md / CLAUDE.md / 00_模板使用说明.md 与模板原文，列出本项目相对模板 vX 定制过的部分（填写的占位符内容、增删过的章节）——这些是升级时的保护对象；
3. 升级方案：把变更分成三类列给我——(a) 纯新增章节/文件，可直接合入；(b) 对未定制部分的修订，可就地更新；(c) 触及本地定制内容的修改，须给出处理建议等我裁决；
4. 执行合并：经我确认后按 (a)→(b)→(c) 顺序合入，保持本地偏差不动；破坏性变更按历史表中的迁移说明逐项执行；
5. 校验收尾：运行 python scripts/verify/verify_placeholders.py 确认无遗漏占位符；核对 .editorconfig/.gitattributes/.gitignore 未丢失；
6. 记忆留痕：把采用记录中的版本号更新为 Y，追加一段本次升级摘要（含我裁决的 (c) 类冲突处理结果）；在 .memory/project/ 新增或更新一条升级决策条目，单独 commit："docs(memory): 升级模板 vX→Y"；
7. 向我汇报升级前后差异总表。
```

## 六、给模板维护者的备忘

- 未来发布新版本时：递增 `00_模板使用说明.md` 头部版本号 → 在"模板版本历史"表追加一行（版本 | 日期 | 变更摘要 | 是否破坏性，破坏性须附迁移说明）→ 在模板主目录 git 打标签 `tpl-vX.Y` → 更新本文件中受影响的提示词文本。
- 各项目的"采用记录"是升级流程的事实起点，启用场景（一~三）的提示词都已包含写入要求，不要省略第 7 条。
